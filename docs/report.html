Project Overview

GlucoSense is a complete, end-to-end system for non-invasive blood glucose estimation using Photoplethysmography (PPG) — a painless optical technique that measures blood volume changes through skin. The system acquires dual-channel (RED + IR) PPG waveforms from a custom-built wearable sensor, processes them through a 12-stage automated signal processing pipeline to extract 24 physiologically-informed biomarkers, and predicts blood glucose in mg/dL using a clinically-validated XGBoost gradient-boosted model. The platform is wrapped in a production-ready full-stack web application with a FastAPI backend and React dashboard — bridging cutting-edge biosignal research to a real clinical interface.

Problem Statement & Motivation
Why Non-Invasive Glucose Monitoring?
🩸Over 537 million adults worldwide live with diabetes (IDF 2021), requiring frequent glucose monitoring
💉Current methods (finger-prick strips, CGM implants) are painful, consumable-dependent, and carry infection risk
📡PPG signals carry rich vascular information correlated with blood analytes — enabling truly painless glucose sensing
⌛A validated PPG-based approach enables integration into everyday wearables (smartwatches, fitness bands)
Sensing Principle — PPG Optics
🔴660 nm RED LED — primarily absorbed by oxyhaemoglobin; glucose modulates optical scattering in tissue
⬛940 nm IR LED — deeper tissue penetration; primary channel for cardiac pulse morphology extraction
📊Differential channel (IR − RED ratio) enhances glucose-correlated components used as additional features

Key Technical Highlights
🔬
Physiologically-informed features — 24 PPG biomarkers spanning statistical moments (skewness, kurtosis), spectral entropy, HRV, TEO energy, pulse morphology (rise/decay time, pulse width, dicrotic notch), and cross-channel differential features across RED, IR, and IR−RED channels.
⚙️
Production-grade DSP pipeline — ~3,000-line Python codebase: Butterworth bandpass filtering, Pan-Tompkins beat detection, adaptive beat rejection, 5 SQI quality metrics (SNR, correlation, amplitude, HRV regularity, morphology), and ensemble beat averaging.
⚖️
Clinical sample weighting — Custom 2× weighting for hyperglycemic subjects (≥130 mg/dL) corrects class imbalance and improves accuracy in the clinically critical elevated-glucose range — a domain-informed ML design decision.
📋
Rigorous multi-metric validation — Evaluated on 5 metrics (MAE, RMSE, R², MAPE, Clarke Error Grid) across train/test split, 5-Fold cross-validation, and per-glucose-range analysis. 12+ tuning runs versioned in a history CSV for full reproducibility.

Signal Processing Pipeline — 12 Stages
  • 1
    Raw CSV Ingestion — Parse UART stream; separate RED & IR channels per sample
  • 2
    Window Slicing — Segment 15-second analysis windows from continuous recordings
  • 3
    Detrending & DC Removal — Eliminate baseline wander and DC offset components
  • 4
    Bandpass Filtering — Butterworth filter 0.5–8 Hz isolates cardiac frequency band
  • 5
    Beat Detection — Pan-Tompkins-inspired peak finder applied on the IR channel
  • 6
    Signal Quality Assessment — 5 SQI metrics: SNR, correlation, amplitude, HRV regularity, morphology consistency
  • 7
    Adaptive Beat Rejection — Outlier and physiologically invalid beats discarded automatically
  • 8
    Ensemble Beat Averaging — Accepted beats time-warped and averaged into a clean representative template
  • 9
    Feature Extraction (per-beat) — 24 biomarkers computed: statistical, spectral, morphological, temporal
  • 10
    Window Averaging — Per-beat features averaged across all accepted beats in the window
  • 11
    Dataset Assembly & Cleaning — NaN removal, IQR-based outlier filtering, glucose label pairing
  • 12
    Robust Scaling & Split — RobustScaler on all features; 80/20 stratified train/test partition
Machine Learning — XGBoost Regressor

Conclusion, Impact & Future Direction
GlucoSense proves that a cost-effective, hardware-level PPG system combined with disciplined signal processing and clinical ML validation can achieve meaningful blood glucose estimation accuracy. The project spans 7+ functional layers — from microcontroller firmware and embedded C code, to automated Python DSP pipelines, XGBoost modelling with 5-fold cross-validation, Clarke Error Grid clinical assessment, and a production-ready REST API with a React web application. The achieved test R² of 0.872, MAE of 4.89 mg/dL, and Clarke Zone A of 91.7% establish a strong proof-of-concept on an initial 75-subject dataset, closely approaching clinical benchmark thresholds. Planned next steps include expanding the dataset to 500+ subjects across broader glucose ranges, integrating a real-time on-device inference engine (TensorFlow Lite on ESP32), and exploring deep learning architectures (1D-CNN, LSTM) on raw PPG waveforms to further close the gap to clinical-grade accuracy.
